# The os Module: Files, Paths, and Processes

## Learning Objectives

- Inspect and change the process environment: cwd, env vars, and exit codes.
- Manage files and directories with `os` and know when `pathlib` is nicer.
- Run external commands safely with `subprocess`.

## Introduction

The `os` module is Python's bridge to the operating system: filesystem state, environment variables, and process control. (Prefer `pathlib` for pure path wrangling - module 10 - but `os` still owns environment and process territory.)

## Environment and Working Directory

```python
import os

print(os.getcwd())                    # current working directory
os.chdir("/tmp")                      # change it
print(os.environ.get("HOME"))         # read an env var safely
os.environ["SCAN_PROFILE"] = "fast"   # set one for this process and its children

if os.environ.get("DEBUG"):
    print("debug mode on")
```

Environment variables are how tools receive configuration without hardcoding: API tokens, feature flags, target lists. `.get()` avoids `KeyError` on missing variables, and you can supply a default: `os.environ.get("TIMEOUT", "5")` - remember the value is always a string.

## Filesystem Operations

```python
os.listdir("logs")              # names in a directory (list of str)
os.makedirs("out/reports", exist_ok=True)   # recursive mkdir, no error if present
os.rename("old.txt", "new.txt")
os.remove("temp.txt")           # delete a file
os.path.exists("app.log")
os.path.getsize("app.log")      # bytes
os.path.join("logs", "app.log") # path join (pathlib's / is nicer)
```

`os.walk` visits a whole tree when `rglob` is not enough control:

```python
for dirpath, dirnames, filenames in os.walk("/var/log"):
    for name in filenames:
        if name.endswith(".gz"):
            print(os.path.join(dirpath, name))
```

## Running External Commands: subprocess

Sometimes the right tool already exists (`nmap`, `git`, `openssl`). `subprocess.run` executes it and captures the result:

```python
import subprocess

result = subprocess.run(
    ["nmap", "-p", "22,80", "scanme.nmap.org"],
    capture_output=True, text=True, timeout=60,
)
print(result.returncode)
print(result.stdout[:200])
```

Two safety rules:

1. **Always pass a list of arguments**, never a glued-together string with `shell=True`. `subprocess.run(f"nmap {user_input}", shell=True)` is a command-injection hole: a `user_input` of `x; rm -rf ~` runs the second command too. The list form passes each element to the program literally.
2. **Set a timeout** on anything that touches the network, or one hung host freezes your script.

`check=True` makes a nonzero exit code raise `CalledProcessError` instead of passing silently.

## Common Mistakes

- `shell=True` with string-built commands - the classic injection bug.
- Assuming the script's cwd is the script's directory; it is wherever the user launched it. Anchor paths to `Path(__file__).parent` when it matters.
- Reading env vars with `os.environ["KEY"]` and crashing when unset; use `.get` with a default.
- Not checking `returncode`, so a failed external command looks like success.

## Key Takeaways

- `os.environ` configures tools via the environment; `.get()` with defaults keeps it robust.
- `os.listdir`/`makedirs`/`rename`/`remove`/`walk` cover filesystem jobs; `pathlib` handles paths more pleasantly.
- `subprocess.run([...], capture_output=True, text=True, timeout=...)` runs external tools; lists and timeouts keep it safe.

from pathlib import Path

## Check Yourself

**Why is `subprocess.run(["nmap", target])` safer than `subprocess.run(f"nmap {target}", shell=True)`?**

<details>
<summary>Show answer</summary>

The list form passes each argument literally to the program. `shell=True` hands the string to a shell, where injected metacharacters in `target` (`;`, `|`, backticks) execute extra commands.
</details>

**What is the type of every value in `os.environ`?**

<details>
<summary>Show answer</summary>

Always a string - convert with `int()` etc. when you need numbers, and handle conversion errors.
</details>

**What does `os.makedirs(path, exist_ok=True)` do differently from `os.mkdir(path)`?**

<details>
<summary>Show answer</summary>

It creates all missing parent directories recursively and does not raise if the directory already exists.
</details>
