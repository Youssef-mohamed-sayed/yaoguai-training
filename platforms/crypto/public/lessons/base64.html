    ENCODING · MODULE 02

    Base64

    Beginner

    In this lesson you will learn:

    • Why binary data can't just be dropped into text formats like JSON or email
    • How Base64 packs bytes into a 64-character alphabet, 6 bits at a time
    • Why Base64 output is ~33% longer than the original data, and what the = padding means
    • Why a Base64 string "looking encrypted" is a beginner trap, not a security property

    Introduction

    You've seen Base64 even if you didn't know its name: image data embedded in HTML (data:image/png;base64,...), JWT tokens, email attachments, API keys. Base64 exists to answer one problem: how do you put arbitrary binary bytes somewhere that only expects plain, printable text?

    Following hex, this is the second encoding you need fluent recognition of — in CTFs, a block of letters/digits/+ / ending in = or == is almost always Base64 on sight.

    History

    Base64 grew out of early email: the original internet mail standard (SMTP) only guaranteed safe delivery of 7-bit ASCII text, so attaching a binary file (an image, a zip) directly would corrupt it in transit. MIME (Multipurpose Internet Mail Extensions, early 1990s) standardized Base64 as the way to encode binary attachments as safe text. The same problem — "I need to put bytes somewhere that only likes text" — still exists today in JSON, URLs and config files, which is why Base64 never went away.

    Brief definition

    DEFINITION

    Base64 represents binary data using a fixed alphabet of 64 printable characters: A-Z a-z 0-9 + / (and = for padding). Each output character encodes 6 bits, so every 3 bytes (24 bits) of input become exactly 4 Base64 characters.

    Why 6 bits? Because 2⁶ = 64 — exactly the size of the alphabet. This is the same idea as hex (2⁴ = 16 symbols, 4 bits per digit), just with a bigger alphabet and fewer characters needed per byte.

    How it works

    Bytes→Group into 3-byte (24-bit) chunks→Split into four 6-bit groups→Look up each in the 64-char table

    Take the letter "M" (byte value 77 = binary 01001101). Base64 needs 3 bytes at a time (24 bits) to divide evenly into four 6-bit groups, so "Man" (3 bytes) is the classic textbook example:

    M       a       n
01001101 01100001 01101110   (24 bits)

010011 010110 000101 101110   (regrouped into four 6-bit chunks)
 19     22      5     46
 T      W       F      u       (looked up in the Base64 table)

"Man" -> "TWFu"

    When the input length isn't a multiple of 3 bytes, the last group is padded with zero bits and the output is padded with = characters so the length still comes out even — that's what those trailing equals signs mean.

    Base64 in Python

    encoding.py 
    import base64

def base64_encode(data: str) -> str:
    return base64.b64encode(data.encode("utf-8")).decode("ascii")

def base64_decode(data: str) -> str:
    return base64.b64decode(data).decode("utf-8", errors="replace")

    Python's standard library does the bit-regrouping for you — base64.b64encode takes raw bytes and returns Base64 bytes, so we decode those to a normal string with .decode("ascii") since Base64 output is always plain ASCII.

    Strengths

    • Safe for text-only channels — guaranteed to survive email, JSON, URLs (with minor variants), XML.
    • Deterministic and lossless — always reversible, exactly.
    • Standardized — every language's standard library implements it the same way.

    Weaknesses

    Base64 provides zero confidentiality — same trap as hex. It is encoding, not encryption: no key, instantly reversible by anyone, including an attacker. Developers sometimes "hide" API keys or passwords in Base64 in config files or source code, which is a false sense of security — a one-line decode recovers them.

    It's also ~33% less space-efficient than raw binary, since 3 bytes always become 4 characters — a real but minor cost, not a security issue.

    Cybersecurity & CTF perspective

    Base64 shows up in HTTP Basic Auth headers, JWTs, cookies, malware configuration blobs, and leaked credential dumps. In forensics and malware analysis, spotting Base64 — and immediately decoding it rather than treating it as "encrypted" — is a reflex you need. In web security, Base64-encoded parameters are a common place to find hidden serialized objects, IDs, or even embedded SQL/command injection payloads once decoded.

    Summary

    • Base64 maps every 3 bytes of input to 4 printable characters from a 64-symbol alphabet.
    • = padding appears when the input length isn't a multiple of 3 bytes.
    • It is encoding, not encryption — never a substitute for a cipher.
    • Encodings can be stacked (Base64 of hex, etc.) — always peel off one layer at a time.
