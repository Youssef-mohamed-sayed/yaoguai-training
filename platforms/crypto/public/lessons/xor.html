    XOR Cipher

    Easy

    In this lesson you will learn:

    • What a key is, and what "symmetric encryption" means — your first real cipher
    • The XOR bit operation and why it's its own inverse
    • How to build a working (if insecure) cipher from it in Python
    • Why reusing a short XOR key is one of the most exploited mistakes in CTF crypto

    Introduction

    So far, hex and Base64 have been encodings: they hide nothing and provide no security. XOR is where the course crosses into real encryption: for the first time, there is a secret (a key), and without it, you can't easily get the plaintext back.

    KEY

    A piece of secret information that controls how encryption and decryption happen. Without the correct key, decryption shouldn't be possible.

    SYMMETRIC ENCRYPTION

    Encryption where the same key is used to both encrypt and decrypt. (Contrast with asymmetric encryption, covered later in RSA, where encryption and decryption use different keys.)

    History

    XOR-based encryption is one of the oldest cipher ideas in practice, closely related to the 19th-century Vigenère cipher (which XORs/shifts letters by a repeating keyword) and to the stream cipher family in general. Its modern significance is really as a building block: it's not deployed directly as "the cipher" in serious systems today, but every stream cipher (including RC4, which you'll meet next) and every block cipher's internals (DES, AES) use XOR constantly as one of their core operations. Learning XOR properly here pays off in every later module.

    Brief definition

    DEFINITION

    XOR ("exclusive or") is a bit operation: it outputs 1 only when its two input bits differ.

    ABA XOR B
    000
    011
    101
    110

    The property that makes XOR useful for a cipher: it's its own inverse. XORing twice with the same value gets you back where you started:

    plaintext  XOR key  =  ciphertext
ciphertext XOR key  =  plaintext      # because A ^ B ^ B = A

    That's why the exact same function can both encrypt and decrypt — there's no separate "reverse" algorithm to write.

    How it works

    Plaintext bytes→Key bytes (repeated/cycled)→XOR byte-by-byte→Ciphertext bytes

    The key is almost always shorter than the message, so it's repeated (cycled): byte i of the data is XORed with byte i % len(key) of the key.

    data = "hello"   key = "ab"

h e l l o
a b a b a     (key repeated/cycled to match length)

    The result is raw, often unprintable bytes — that's why the API returns XOR ciphertext as hex (you already know how to read that).

    Two messages were encrypted with the same XOR key: C1 = P1 ⊕ K and C2 = P2 ⊕ K. What do you get if you compute C1 ⊕ C2?

    The key, K

    XOR in Python

    stream_core.py 
    def xor_crypt_bytes(data: bytes, key: bytes) -> bytes:
    return bytes(b ^ key[i % len(key)] for i, b in enumerate(data))

    One line: XOR every data byte with the matching (cycled) key byte. encryption.py and decryption.py both call this exact same function — proof that XOR really is its own inverse.

    calling it 
    result = xor_encrypt("hello", "key")
print(result)    # hex ciphertext

back = xor_decrypt(result, "key")
print(back)      # hello

    Practical tasks

    TASK 04decode

    This was encrypted with a single repeating-byte key: plaintext "BBBB" under key "A" gives ciphertext byte 0x03 repeated four times (since 'B' ^ 'A' = 0x42 ^ 0x41 = 0x03). Using the same logic, if the key is "A" (0x41) and the ciphertext hex is 040405041d, what's the plaintext? (XOR each ciphertext byte with 0x41, then read as ASCII.)

    Strengths

    • Extremely fast — a single bit operation per byte, trivial for hardware and software alike.
    • Foundational — understanding XOR here makes RC4, DES and AES's internals much easier to follow.
    • Perfect security is possible — as a One-Time Pad: if the key is truly random, at least as long as the message, and never reused, XOR becomes mathematically unbreakable.

    Weaknesses

    Algorithm weakness: a short, reused key makes patterns in the plaintext (repeated letters, spaces, headers) leak straight through into the ciphertext — identical to the historical weakness of the Vigenère cipher.

    Implementation weakness: even with XOR used "correctly" in principle, developers often reuse the same short key across many messages for convenience — which is exactly the One-Time-Pad rule being broken, and exactly what Task 02 above showed how to exploit.

    If an attacker knows or guesses even a small part of the plaintext (a known header, a common word), XORing it against the matching ciphertext reveals that slice of the key directly — a known-plaintext attack.

    Cybersecurity & CTF perspective

    Single-byte and repeating-key XOR are CTF staples precisely because they're easy to set up and easy to break with the right technique: brute-forcing all 256 single-byte keys, or using frequency analysis / "crib dragging" for longer keys. Malware also uses XOR constantly to obfuscate strings and payloads against simple signature scanners — reverse engineers routinely XOR-brute-force suspicious byte blobs as a first move.

    CTF Challenge

    CHALLENGE · BROKEN XOREasy
    SCENARIO

    A developer XOR-"encrypted" a flag with a single repeating ASCII key, believing it was secure because the output "doesn't look readable."

    OBJECTIVE

    Recover the flag. The key is a single lowercase letter.

    GIVEN DATA (hex ciphertext)
    0b1d1d141a4a0b071f4a1b1f0b1a111f164a164a150b1a4a0817
    FLAG FORMAT

    flag{...}

    Hint 1

    With a 1-byte key there are only 256 possibilities — brute force every value 0x00–0xff and look for printable ASCII that starts with "flag{".

    Hint 2

    You know the plaintext almost certainly starts with "f". XOR the first ciphertext byte (0x0b) with ASCII "f" (0x66) to recover a key candidate directly, then test it against the rest.

    Show solution
    REASONING

    0x0b ^ 0x66 ('f') = 0x6d ('m'). Trying key "m" against the whole ciphertext decodes cleanly to the flag.

    PYTHON
    ct = bytes.fromhex("0b1d1d141a4a0b071f4a1b1f0b1a111f164a164a150b1a4a0817")
for k in range(256):
    pt = bytes(b ^ k for b in ct)
    if pt.startswith(b"flag{"):
        print(pt.decode())
    FLAG

    flag{xor_key_reuse_is_fatal}

    Summary

    • XOR encrypts and decrypts with the same operation and the same key.
    • Security depends entirely on the key: random, full-length, never reused = unbreakable (One-Time Pad). Short and reused = broken.
    • Single-byte XOR is brute-forceable in 256 tries; this is a foundational CTF technique.
    • XOR is a building block inside every stream and block cipher you'll meet next.
