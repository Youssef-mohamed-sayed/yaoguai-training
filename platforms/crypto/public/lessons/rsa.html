    Introduction

    RSA is the other half of public-key cryptography: where Diffie–Hellman agrees on a shared secret, RSA lets anyone encrypt a message using a key that's completely public — and only the holder of a matching private key can decrypt it. This is the biggest conceptual jump in the course: for the first time, encryption and decryption use different keys.

    History

    RSA was published in 1977 by Ron Rivest, Adi Shamir, and Leonard Adleman (its name is their initials), shortly after Diffie–Hellman introduced the idea of public-key cryptography but before anyone had a practical public-key encryption scheme (Diffie-Hellman only does key exchange). RSA filled that gap, and (separately discovered a few years earlier but classified at UK intelligence agency GCHQ) remains one of the two or three most widely deployed public-key systems in the world — behind HTTPS certificates, SSH, PGP email, and code-signing.

    Brief definition

    DEFINITION

    RSA is a public-key (asymmetric) encryption scheme: a public key (e, n) can encrypt, but only the matching private key (d, n) can decrypt — built on the difficulty of factoring the product of two large primes.

    PUBLIC KEY / PRIVATE KEY

    The public key is shared with anyone — it provides no way to decrypt. The private key is kept secret by its owner and is the only thing that can reverse an RSA encryption.

    RSA's security rests on a different hard problem than Diffie–Hellman's: given a very large number n that's the product of two large primes p and q, finding p and q (factoring n) is believed to be computationally infeasible for large enough numbers — even though multiplying p × q in the first place is trivial.

    How it works

    Pick primes p, q→n = p×q, compute Ï†(n)→Choose public e, derive private d→Encrypt: c = m^e mod n→Decrypt: m = c^d mod n

    Key generation

    1. Pick two large random primes, p and q. Compute n = p × q — this becomes part of both keys.
    2. Compute Ï†(n) = (p-1)(q-1) (Euler's totient — a value tied to how many numbers below n share no common factor with it).
    3. Choose a public exponent e (commonly 65537) that shares no common factor with Ï†(n).
    4. Compute the private exponent d, the modular inverse of e mod Ï†(n) — the one number satisfying (e × d) mod Ï†(n) = 1.

    Public key: (e, n). Private key: (d, n). p, q, and Ï†(n) are discarded/kept secret — if anyone recovers them from n (by factoring it), they can compute d themselves and break the key entirely.

    Encrypt / decrypt

    Treating the message m as a number smaller than n: ciphertext c = m^e mod n, and plaintext m = c^d mod n. The matching exponents e and d are mathematically constructed (via Ï†(n)) so this round-trips exactly.

    RSA in Python

    rsa_core.py (shape of the implementation) 
    def generate_keypair(bits=512):
    p = _generate_prime(bits // 2)
    q = _generate_prime(bits // 2)
    n = p * q
    phi = (p - 1) * (q - 1)
    e = 65537
    d = _modinv(e, phi)
    return (e, n), (d, n)   # (public_key, private_key)

def rsa_encrypt_int(m: int, e: int, n: int) -> int:
    return pow(m, e, n)

def rsa_decrypt_int(c: int, d: int, n: int) -> int:
    return pow(c, d, n)
    public_key, private_key = rsa_generate_keys(bits=512)
e, n = public_key
d, _ = private_key

ciphertext = rsa_encrypt("hi", e, n)
print(ciphertext)

plaintext = rsa_decrypt(ciphertext, d, n)
print(plaintext)   # hi

    Strengths

    • True public-key encryption — anyone can encrypt to you using only your public key, with no prior shared secret.
    • Also enables digital signatures — the roles of e and d can be flipped, letting you "sign" with your private key so anyone can verify with your public key.
    • Decades of scrutiny — with proper key sizes (2048+ bits today) and proper padding, RSA remains trusted and widely deployed.

    Weaknesses

    Algorithm weakness — textbook RSA without padding is deterministic (same message always encrypts to the same ciphertext) and malleable (an attacker can manipulate ciphertexts in predictable ways without knowing the key), plus vulnerable to small-exponent attacks like the one in Task 03. RSA should be taught and used with appropriate padding (OAEP), never as raw textbook math in production.

    Implementation weakness — small or poorly generated primes: if p and q aren't large enough, or aren't properly random (shared between unrelated keys, generated from a weak source of randomness, or close together in value), n becomes factorable — directly recovering the private key. This project's bits=512 default is intentionally small for teaching speed; real RSA keys use 2048+ bits specifically because 512-bit RSA has been practically factored by researchers.

    Cybersecurity & CTF perspective

    RSA CTF challenges are a genre of their own: factoring a deliberately small or weak n, exploiting a shared prime factor between two different public keys (a classic and surprisingly realistic mistake), Wiener's attack against a too-small private exponent d, and small-exponent/no-padding attacks like Task 03's. Tools like factordb.com and libraries like sympy or RsaCtfTool are standard CTF kit for exactly these scenarios. RSA is also central to real-world security work: TLS certificate analysis, SSH key auditing, and PGP/GPG all rest on these same primitives.

    CTF Challenge

    CHALLENGE · TINY MODULUSAdvanced
    SCENARIO

    A deliberately weak RSA key was generated for a demo: n = 3233, e = 17. You intercepted the ciphertext c = 2790 (a single small integer, no padding).

    OBJECTIVE

    Factor n, derive the private key, and recover the plaintext integer m.

    FLAG FORMAT

    flag{m} — the recovered plaintext integer

    Hint 1

    3233 is small enough to factor by trial division: try every prime up to its square root (~57).

    Hint 2

    3233 = 61 × 53. Compute Ï†(n) = 60 × 52, then find d as the modular inverse of 17 mod Ï†(n).

    Show solution
    PYTHON
    n, e, c = 3233, 17, 2790
p, q = 61, 53                      # 61 * 53 = 3233, found by trial division
phi = (p - 1) * (q - 1)            # 3120
d = pow(e, -1, phi)                # modular inverse of e mod phi
m = pow(c, d, n)
print(m)   # 65
    FLAG

    flag{65}

    Summary

    • RSA is asymmetric: a public key (e, n) encrypts, a private key (d, n) decrypts.
    • Security rests on the difficulty of factoring n = p × q back into its prime factors.
    • Textbook RSA (raw, unpadded math) has real exploitable weaknesses — always use proper padding in practice.
    • This closes the encryption category: symmetric (XOR → RC4 → DES → 3DES → AES) to asymmetric (Diffie-Hellman → RSA). Hashing is next.
