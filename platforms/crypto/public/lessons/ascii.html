    ASCII

    Beginner

    In this lesson you will learn:

    • What the ASCII table actually is, and why it only needs 128 values
    • How ord()/chr() convert between characters and numbers
    • Why this is the foundation hex, Base64, and UTF-8 all build on
    • How to read a CTF message given only as a list of numbers

    Introduction

    You've been reading byte values since the Hex lesson ("H" = 72, "e" = 101...) without a name for why. ASCII is that name: the table that assigns every common keyboard character a number from 0 to 127. It's the smallest, oldest piece of the puzzle — but almost every bug, encoding trick, and obfuscation technique later in this course assumes you know it cold.

    History

    ASCII ("American Standard Code for Information Interchange") was standardized in 1963, when different computer manufacturers each used incompatible character codes, making it hard to exchange text between machines. ASCII fixed that by agreeing, industry-wide, on one number per character. It used 7 bits (0–127), covering English letters, digits, punctuation, and a handful of non-printable "control characters" left over from teletype machines (like newline and tab). It's still the foundation of modern text today — UTF-8, the encoding behind most of the internet, was deliberately designed so that any plain ASCII text is already valid UTF-8, unchanged.

    Brief definition

    DEFINITION

    ASCII is a fixed table mapping 128 characters (letters, digits, punctuation, and control characters) to the numbers 0–127.

    CharacterDecimalHex
    'A'650x41
    'a'970x61
    '0'480x30
    ' ' (space)320x20

    Notice 'a' (97) is exactly 32 more than 'A' (65) — uppercase and lowercase letters are a fixed offset apart, which is why case-shifting a letter is just adding or subtracting 32.

    How it works

    Character→Look up in the ASCII table→Decimal (or binary / hex) value

    Encoding is just a table lookup in one direction; decoding is the same table read backwards. There's no computation, no key — it's pure, fixed correspondence, which is why it's the simplest "encoding" in this course even simpler than hex (hex is actually built on top of the byte values ASCII assigns).

    ASCII in Python

    encoding.py 
    def ascii_encode(data: str) -> list:
    return [ord(ch) for ch in data]

def ascii_decode(codes) -> str:
    return "".join(chr(c) for c in codes)

    Python's built-in ord() and chr() are the ASCII table lookup in each direction.

    codes = ascii_encode("hi")
print(codes)              # [104, 105]
print(ascii_decode(codes))  # hi

    Strengths

    • Universal — every modern text encoding (UTF-8 included) agrees with ASCII for the characters it covers.
    • Simple and fast — a direct table lookup, nothing to compute.
    • Human-readable for the characters it covers (unlike, say, raw binary).

    Weaknesses

    Zero confidentiality — exactly like hex and Base64, this is representation, not protection. There's no key, and the table is public and fixed.

    ASCII's other practical limitation (not a security weakness) is that 128 values aren't enough for every language's alphabet — accented letters, Arabic, Chinese, emoji, etc. all needed Unicode/UTF-8 to extend far beyond ASCII's original range, while staying backward-compatible with it.

    Cybersecurity & CTF perspective

    Fluency in ASCII values is a background skill behind almost every other module: reading raw memory dumps, recognizing a string hidden as decimal/hex/octal byte values in a CTF challenge, understanding buffer-overflow payloads (which are built byte-by-byte), and reasoning about case-shift or Caesar-style obfuscation (which exploit ASCII's fixed letter ordering and the A/a offset you found in Task 01).

    Summary

    • ASCII maps 128 characters to numbers 0–127 — a fixed, public table.
    • ord()/chr() move between a character and its code.
    • No confidentiality — it's the foundation every other encoding in this course builds on.
    • UTF-8 is a superset that's backward-compatible with plain ASCII.
