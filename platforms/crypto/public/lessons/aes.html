    Introduction

    AES is the block cipher behind almost everything that needs real confidentiality today: HTTPS, disk encryption, VPNs, messaging apps, password managers. After XOR (a single bit operation) this is a much bigger step up — AES processes data in fixed-size blocks and runs multiple rounds of structured, reversible scrambling, all driven by a secret key.

    BLOCK CIPHER

    A cipher that encrypts data in fixed-size chunks ("blocks") rather than bit-by-bit or byte-by-byte like a stream cipher. AES's block size is always 128 bits (16 bytes), regardless of key size.

    History

    AES didn't appear in isolation — it directly replaced DES (which you'll study next in the course, but is worth naming here): DES's 56-bit key became brute-forceable by the late 1990s as hardware got cheaper. In 1997 the US National Institute of Standards and Technology (NIST) ran an open, public competition for DES's replacement; the winning design, submitted by Belgian cryptographers Joan Daemen and Vincent Rijmen under the name Rijndael, was standardized as AES in 2001. It remains the global standard today, with no practical break of the full algorithm found in over two decades of public scrutiny.

    Brief definition

    DEFINITION

    AES is a symmetric block cipher that encrypts fixed 128-bit blocks of data using a secret key, through a fixed number of structured rounds of substitution and permutation.

    This project implements AES-128: a 128-bit (16-byte) key, a 128-bit (16-byte) block, and 10 rounds. (AES-192 and AES-256 just use longer keys and more rounds — 12 and 14 — the per-round steps are identical.)

    CIPHER

    An algorithm for encrypting and decrypting data.

    ROUND

    One repetition of a fixed sequence of transformations, applied multiple times to increase security. AES-128 repeats its round 10 times.

    How AES works

    Explained step by step, from the simplest view down to the actual operations.

    16-byte block→4×4 state grid→10 rounds of mixing→16-byte ciphertext

    The "state"

    AES treats each 16-byte block as a 4×4 grid of bytes (the "state"), filled column by column. Every round operation works on this grid, not on a flat row of bits like DES does.

    Key expansion

    The single 128-bit key is expanded into 11 round keys (one for the initial step, plus one per round), each 16 bytes, using a schedule that mixes in a substitution table and a round constant so every round key is different from the raw key and from each other.

    The four round operations

    Every round (except special-cased first/last steps) applies these four operations, in order:

    1. SubBytes — every byte in the state is replaced by looking it up in a fixed 256-entry substitution table (the S-box). This is the non-linear step that resists algebraic attacks.
    2. ShiftRows — row 0 of the grid is untouched; row 1 shifts left by 1 byte, row 2 by 2, row 3 by 3. This spreads each byte's influence across columns.
    3. MixColumns — each column of 4 bytes is multiplied by a fixed matrix using finite-field (GF(2⁸)) arithmetic, mixing bytes within a column so every output byte depends on every input byte of that column. (Skipped in the final round.)
    4. AddRoundKey — the state is XORed with that round's 16-byte round key. (Yes — the XOR you just learned is doing real work here.)
    full flow 
    AddRoundKey (round 0 key)
for rounds 1..9:
    SubBytes -> ShiftRows -> MixColumns -> AddRoundKey
round 10 (final, no MixColumns):
    SubBytes -> ShiftRows -> AddRoundKey

    Decryption runs the inverse of every step in reverse order — inverse S-box, inverse ShiftRows (shift right), inverse MixColumns (a different fixed matrix) — applying round keys starting from the last one.

    Why SubBytes/MixColumns matter: Claude Shannon described two properties every good cipher needs — confusion (the key-to-ciphertext relationship should be as complex as possible; SubBytes' non-linear lookup provides this) and diffusion (one changed input bit should affect many output bits; ShiftRows + MixColumns spread influence across the whole block). After a couple of rounds, every output byte depends on every input byte and every key byte.

    AES in Python

    This project's aes_core.py implements AES-128 from scratch and was verified against the official FIPS-197 test vector (key 000102030405060708090a0b0c0d0e0f, plaintext 00112233445566778899aabbccddeeff → ciphertext 69c4e0d86a7b0430d8cdb78070b4c55a).

    aes_core.py (shape of the implementation) 
    def _encrypt_block(block, round_keys):
    state = _add_round_key(block, round_keys[0])
    for rnd in range(1, 10):
        state = _sub_bytes(state)
        state = _shift_rows(state)
        state = _mix_columns(state)
        state = _add_round_key(state, round_keys[rnd])
    state = _sub_bytes(state)
    state = _shift_rows(state)
    state = _add_round_key(state, round_keys[10])
    return state

    PADDING

    Real data is rarely an exact multiple of 16 bytes. PKCS7 padding adds bytes to round the plaintext up to the next full block before encrypting, and strips them back off after decrypting.

    Strengths

    • No practical cryptanalytic break of the full algorithm exists after 20+ years of public attack attempts.
    • Fast — modern CPUs have dedicated AES instructions (AES-NI), making it fast enough for full-disk and full-traffic encryption.
    • Flexible key sizes — 128/192/256-bit, letting you trade a little speed for a larger security margin.

    Weaknesses

    Implementation weakness — ECB mode: this project applies AES directly block-by-block (ECB) to teach the algorithm's internals clearly. ECB is insecure for real use: identical plaintext blocks always produce identical ciphertext blocks, visibly leaking structure. The classic demonstration is an ECB-encrypted bitmap image where you can still make out the original picture's outline in the ciphertext.

    Real systems use a mode such as AES-GCM or AES-CBC with a random IV (Initialization Vector) specifically to prevent this. This is a mode/implementation issue, not a flaw in the AES algorithm itself — the distinction matters: AES the cipher is sound; AES used in ECB mode is not.

    IV (Initialization Vector)

    A random value mixed in before encryption so that encrypting the same plaintext twice (with the same key) produces different ciphertext each time.

    Cybersecurity & CTF perspective

    "Spot the ECB" is one of the most common AES CTF categories: given a ciphertext, look for repeated 16-byte blocks, which only happen in ECB mode with repeated plaintext. AES challenges also frequently target key management mistakes — hardcoded keys found in a binary, keys reused across unrelated messages, or keys derived predictably from something public (a timestamp, a username) — rather than attacking the math of AES itself, which is exactly why "the algorithm vs. the implementation" distinction from the weaknesses section is a core cybersecurity skill, not just trivia.

    CTF Challenge

    CHALLENGE · SPOT THE ECBIntermediate
    SCENARIO

    A login form encrypts a session blob with AES-ECB. The blob is built by concatenating known fields, and one of them repeats across the ciphertext.

    OBJECTIVE

    Without the key, identify which 16-byte ciphertext block repeats, proving ECB mode is in use (the real flag is about recognizing the structural leak, not decrypting).

    GIVEN DATA (hex, 16-byte blocks separated by spaces)
    1f2a3b4c5d6e7f80 9a0b1c2d3e4f5061 1f2a3b4c5d6e7f80 72839405a6b7c8d9
    FLAG FORMAT

    flag{...} — the flag text itself (not the repeated block hex)

    Hint 1

    Compare each 16-byte block to every other block. ECB guarantees identical plaintext blocks become identical ciphertext blocks.

    Hint 2

    Blocks 1 and 3 are identical — that repetition is only possible in ECB mode.

    Show solution
    REASONING

    Block 1 (1f2a3b4c5d6e7f80) and block 3 are byte-for-byte identical. Under ECB, that's only possible if the corresponding 16-byte plaintext chunks were identical too — a direct structural leak with zero cryptanalysis required.

    PYTHON
    blocks = [ct[i:i+16] for i in range(0, len(ct), 16)]
print(len(blocks) != len(set(blocks)))  # True -> ECB mode detected

    Summary

    • AES-128 encrypts 16-byte blocks through 10 rounds of SubBytes, ShiftRows, MixColumns, AddRoundKey.
    • The algorithm itself has no known practical break after decades of scrutiny.
    • Real-world security depends just as much on the mode (never ECB) and on key management as on the cipher itself.
    • CTF AES challenges usually target the implementation, not the math.
