    Introduction

    SHA-1 is MD5's sturdier sibling â€” same purpose (a one-way digest), same general shape of algorithm (padding, working buffers, rounds of mixing), but a wider output. It had a longer security life than MD5, but met the identical fate: practical collisions, eventually found, retired it for anything security-critical.

    History

    SHA-1 ("Secure Hash Algorithm 1") was designed by the US National Security Agency and published by NIST in 1995, as part of the SHA family succeeding the earlier SHA-0. For over a decade it was the default secure hash â€” used in TLS certificates, Git commit hashes, and software signing. Cryptanalysts chipped away at it theoretically for years, and in 2017 Google and CWI Amsterdam published "SHAttered," the first practical SHA-1 collision â€” two different PDF files with identical SHA-1 hashes. Major browsers and certificate authorities phased it out shortly after.

    Status today: Educational / Legacy / Insecure for security purposes

    Brief definition

    DEFINITION

    SHA-1 is a hash function producing a 160-bit (20-byte, 40 hex character) digest from an input of any length â€” one-way, deterministic, no key, same as MD5 but with a wider output and a different internal mixing schedule.

    How it works

    Structurally close to MD5 but not identical: SHA-1 keeps five 32-bit buffers (not four), and each 512-bit block is processed through 80 steps (4 rounds of 20), each step rotating and mixing the buffers with a round-specific nonlinear function, a message-derived word, and a round constant. Like MD5, every step is one-way mixing â€” there's no algebraic inverse that recovers the input from the digest.

    Strengths

    • Wider digest than MD5 (160 vs. 128 bits), which resisted collision attacks longer.
    • Still fine for non-security uses â€” Git, for instance, still uses SHA-1 for commit identifiers, where the threat model (detecting accidental corruption, not resisting a deliberate attacker) is different from a security boundary.

    Weaknesses

    Algorithm weakness: SHA-1 has known, practical collision attacks (the 2017 "SHAttered" demonstration) â€” two different inputs engineered to produce the identical digest. SHA-1 has known collision weaknesses and should not be used anywhere a security guarantee depends on uniqueness (certificates, signatures, integrity against a deliberate attacker).

    Implementation weakness â€” speed, for passwords: exactly as with MD5, SHA-1 is fast, making it unsuitable for password storage regardless of its collision status â€” GPUs compute SHA-1 nearly as fast as MD5.

    Cybersecurity & CTF perspective

    Finding SHA-1 in a modern system (an old certificate, an outdated signing process, a legacy git-based integrity check used as a security boundary) is itself a finding in a security audit. In CTFs, SHA-1 challenges mirror MD5's â€” cracking unsalted digests via wordlists â€” plus occasionally referencing the SHAttered-style collision concept directly (recognizing why "same hash" no longer proves "same file").

    Summary

    • SHA-1 produces a 160-bit digest through 80 steps of mixing across 5 working buffers.
    • Practical collisions (SHAttered, 2017) retired it for integrity/signature use.
    • Still fast â€” still wrong for passwords, same as MD5.
    • SHA-256 (next module) is the modern, currently-trusted replacement.
