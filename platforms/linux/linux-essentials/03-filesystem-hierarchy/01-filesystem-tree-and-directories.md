# The Filesystem Tree and Important Directories


## Learning objectives
- Navigate the Linux directory tree from `/` with confidence.
- Explain the purpose of every major top-level directory.
- Know where configuration, logs, and variable data live before you ever need them in an incident.

## Introduction
Linux presents all storage through **one directory tree**. The top of that tree is `/`, the root directory. Additional disks, partitions, network shares, and even virtual kernel filesystems are **mounted** at directories inside this single tree, so unlike Windows there are no drive letters: your second disk might simply appear as `/mnt/data`.

Learning this map early pays off constantly. When a service fails, its configuration is in `/etc` and its logs are in `/var/log`. When a disk fills, the answer is almost always somewhere under `/var` or `/home`. You will use this lesson's table for the rest of your career.

## Important directories

| Path | Purpose |
|---|---|
| `/` | Root of the directory tree |
| `/home` | Regular users' home directories |
| `/root` | The root account's home directory (not the same as `/`) |
| `/etc` | Host-specific system configuration |
| `/var` | Variable data: logs, queues, caches, service state |
| `/tmp` | Temporary files; cleanup policy varies |
| `/usr` | Most user-space programs, libraries, and shared data |
| `/bin`, `/sbin` | Essential commands; usually symlinks into `/usr` on modern merged-usr systems |
| `/opt` | Optional/add-on application software |
| `/dev` | Device interfaces (disks, terminals, `/dev/null`) |
| `/proc` | Virtual process and kernel information |
| `/sys` | Kernel device and subsystem information |
| `/boot` | Bootloader and kernel images |
| `/mnt` | Conventional temporary mount point |
| `/media` | Where desktop systems auto-mount removable media |

Three of these deserve special respect:

- **`/etc`** holds the configuration that defines how this particular machine behaves: users (`/etc/passwd`), network settings, SSH policy (`/etc/ssh/sshd_config`), and service definitions. Back up a file before editing it, and edit deliberately.
- **`/var/log`** is where the system tells you what happened: authentication attempts (`auth.log` or the journal), package history, service errors. During any investigation, this is your first stop.
- **`/proc` and `/sys`** are **virtual filesystems**. Their entries are generated by the kernel on the fly and represent live kernel state, not stored files. Reading them is safe and informative (`cat /proc/cpuinfo`); writing to them changes a running kernel, so do not edit them casually.

### Configuration and logs
The pattern to memorize: configuration in `/etc/`, logs in `/var/log/`, service data under `/var/lib/`. Exact files depend on distribution and service. On systemd systems, much logging lives in the journal rather than plain files; `journalctl` (module 07) is how you read it.

## Commands
```bash
pwd
ls /
ls -la /etc
ls -ld /var/log
cd /var/log && pwd
```

Sample output:

```text
$ ls -ld /var/log
drwxr-xr-x 10 root syslog 4096 Nov 25 03:58 /var/log
```

`ls -d` lists the directory itself rather than its contents: essential when you want a directory's own permissions. `man hier` documents this whole hierarchy on most systems.

**Exercise 2.** Find three real configuration files and one real log on your system, and print the first lines of one of the configuration files.

**Exercise 3.** Prove that `/proc` is virtual: check the apparent size of `/proc/cpuinfo` and of a real file, and explain the difference.

<details>
<summary>Show a worked solution</summary>

```bash
ls -l /proc/cpuinfo /etc/hostname
```

Output:

```text
-r--r--r-- 1 root root 0 Nov 25 04:12 /proc/cpuinfo
-rw-r--r-- 1 root root 8 Nov 20 12:00 /etc/hostname
```

`/proc/cpuinfo` reports size 0 yet prints pages of content when read: the kernel generates it on demand. The size field is meaningless for virtual files.
</details>

## Check yourself
Answer each question, then open the answer to verify.

**Q1.** What is the difference between `/` and `/root`?

<details>
<summary>Show answer</summary>

`/` is the root of the entire directory tree. `/root` is the home directory of the root user, one directory inside that tree. The shared word "root" causes endless confusion; the two are unrelated concepts.
</details>

**Q2.** A colleague cannot find the second disk they attached, because "there is no D: drive". Where should they look, and why?

<details>
<summary>Show answer</summary>

Anywhere in the single tree where it was mounted: conventionally under `/mnt` or `/media`, or wherever the administrator chose. Linux mounts every filesystem into the one tree under `/`; there are no drive letters.
</details>

**Q3.** A web application fails to start. Which two directories do you check first, and for what?

<details>
<summary>Show answer</summary>

`/etc` for the service's configuration (wrong port, wrong path, bad syntax) and `/var/log` (or `journalctl`) for the error it logged when it tried to start.
</details>

## Common mistakes
- Confusing `/` with `/root`.
- Assuming every machine has the same contents under `/home` (only that machine's users appear there).
- Treating `/proc` like persistent disk storage or editing it casually.
- Editing files in `/etc` without a backup or without reading the file first.

## Key takeaways
The filesystem is one tree; every disk and device lives somewhere inside it. Configuration is in `/etc`, logs in `/var/log`, live kernel state in `/proc` and `/sys`. Learn the map before changing anything on it.

## Further practice
Inspect `/etc/os-release`, `/etc/hostname`, and `/var/log` without modifying them, then read `man hier` once, slowly. It is one of the highest-value man pages in the system.
